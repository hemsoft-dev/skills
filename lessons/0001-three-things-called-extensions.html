Three things called extensions

By the end, you can reject plugin work you already know and spot the runtime API that is actually new.

The useful finding. Copilot CLI extensions are not plugins. They are experimental JavaScript processes that join the live session through the Copilot SDK.

Classify by behavior

Plugin

Installs a bundle of agents, skills, hooks, MCP servers, and LSP configuration. It solves distribution.

CLI extension

Runs beside the CLI, observes events, keeps state, and adds tools, commands, or terminal forms.

Canvas extension

Runs in the Copilot app's side panel as a shared visual artifact for people and agents.

The architectural difference

A skill gives the model instructions. An MCP server gives the model remote tools. A CLI extension joins the session itself:

extension.mjs → joinSession(...) → events + state + tools + commands + UI requests

That lets an extension measure tool duration, count usage across turns, react to lifecycle events, or ask the user for structured input. A plugin can distribute agents, skills, hooks, MCP, and LSP configuration, but it does not replace this executable runtime.

Canvas goes one step further. It gives people and agents the same persistent visual artifact in the app side panel. The CLI TUI can show host-provided dialogs and forms, but GitHub does not document a stable free-form layout API for it yet.

Retrieval check

Which choice can observe every tool call and retain a running total during one session?

Read the primary source

Read GitHub's CLI extension tutorial, especially the tool-time example. It proves the key capability by subscribing to tool execution events and keeping state in a long-lived process.
