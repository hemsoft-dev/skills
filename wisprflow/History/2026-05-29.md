# 2026-05-29

## 13:09 - Created Wispr Flow Troubleshooting Skill

Created skill from extensive debugging session. Key findings:

**Root cause chain:**

1. Sleep/wake at 11:04→11:18 corrupted keyboard hook state (stale keys, missed releases)
2. Restarting Wispr Flow partially restored hook (received simulated keys)
3. But physical keyboard events NOT processed internally by hook (pass-through to other apps worked fine)
4. Config UI relies on Helper IPC for key capture — broken when hook is in bad state
5. Many shortcuts use LWin (VK 91) which Windows 25H2 may guard at shell level

**What was tried (in order):**

- Identified sleep/wake desync from accessibility.log
- Killed and restarted all Wispr Flow processes
- Added AHK Ctrl+Shift+W restart hotkey to Documents\AutoHotkey.ahk
- Eliminated M365Copilot as culprit (killed, no change)
- Eliminated Razer, Logitech G Hub, AutoHotkey, Stream Deck, iCUE (killed all, no change)
- Killed just Helper — respawned with dead hook
- Full clean restart — hook initialized but still didn't process physical keys for shortcut matching
- Confirmed keyboard works fine in all other apps (Keychron USB-C, standard HID)
- Verified 6 keyboard devices OK at driver level, no third-party filter drivers
- No public reports of this specific issue found online

**Resolution**: User will reboot (always fixes hook state issues). Skill created for future reference.

**User's setup**: Keychron USB-C keyboard, Razer + Corsair + Logitech peripherals, Windows 11 25H2, Wispr Flow v1.5.530 Pro.
