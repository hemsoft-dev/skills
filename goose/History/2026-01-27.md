## 23:56 - Documented Windows Update Workaround

**Context:** User encountered WSL error when running `goose update`:

```
WSL ERROR: CreateProcessCommon:800: execvpe(/bin/bash) failed: No such file or directory
```

**Issue:** The `goose update` command relies on a bash script that requires WSL. When WSL is broken/unconfigured on Windows, the update fails completely.

**Solution Implemented:**

- Manually downloaded `goose-x86_64-pc-windows-gnu.zip` from GitHub releases (v1.21.2)
- Extracted to temp directory and copied `goose-package\*` contents to `~\.local\bin\`
- Successfully updated from v1.20.1 → v1.21.2

2. **Key Learnings:**
   - Goose releases use asset name: `goose-x86_64-pc-windows-gnu.zip`
   - Archive contains `goose-package/` subdirectory with `goose.exe` + DLL dependencies
   - All files must be copied together to `~\.local\bin\`
   - WSL error is a known limitation, not a bug

**Why This Matters:**

- Many Windows users don't have WSL configured
- The built-in updater provides NO fallback or helpful error message
- Manual update is actually simple once you know the asset structure
- This workaround is more reliable than depending on WSL
