Quick reference

CLI extension capability map

A Copilot CLI extension is a long-lived Node.js process attached to one live session.

Capability Who initiates it Good examples Contract status
Custom tool Copilot chooses it from its name, description, and JSON Schema. Repository health, release evidence, local service status, domain-specific calculations. Documented CLI extension contract.
Slash command The user runs it directly. /sessionstats, /handoff, /releasecheck. Documented CLI extension contract.
Session events The CLI emits them while the agent works. Tool duration, failures, token use, turn completion, audit logs. Demonstrated by GitHub's tutorial and SDK event reference.
Session state The extension updates ordinary module variables. Running totals, active process IDs, cached API results, workflow state. In memory for one session. Write to disk for longer persistence.
Terminal UI The extension requests a dialog from the host. Confirm, select, text input, and JSON Schema forms. SDK capability. Check session.capabilities.ui?.elicitation first.
Shell process The extension starts or stops it through the session RPC. Cancelable tests, dev servers, benchmarks, log streaming. Present in the CLI changelog and SDK RPC. Verify the bundled version.
Canvas UI The Copilot app hosts the visual interface. Kanban boards, triage boards, documents, dashboards. Documented for the app, not as a free-form CLI TUI API.
Security boundary. The extension process runs local JavaScript with your account's operating-system privileges. CLI permission prompts do not turn untrusted extension code into safe code.

Lifecycle

discover → start process → join session → register capabilities → observe and act → reload or stop

Use /extensions manage for status and logs. Use /extensions mode to choose Load & Augment, Load Only, or Disabled.
